# PC 端个人资料页设计

## 目标

为已登录的博客用户提供只读个人资料页。用户点击 PC 端左侧栏底部的账户区域后，进入独立页面查看自己的资料。

本次只覆盖 PC 用户端，不修改移动端、小程序、文章页面和管理后台。页面不提供昵称、邮箱或手机号的编辑能力。

## 入口与路由

- 当用户已登录时，侧栏底部的账户按钮（头像、昵称或邮箱所在整块区域）可点击。
- 点击后关闭当前下拉菜单并跳转到 `/profile`。
- 账户下拉菜单保留现有的账户摘要和退出登录操作，不新增重复的“个人资料”入口。
- 新路由命名为 `profile`，使用现有用户端布局和 `SiteHeader`，不进入后台布局。

## 页面结构

页面沿用博客现有暖白背景、衬线标题和窄阅读栏视觉，不引入新的全屏卡片样式。

1. 顶部放置“返回首页”链接。
2. 标题区显示圆形首字母头像、昵称和“个人资料”标题。
3. 资料区为带分隔线的两列信息列表：左侧字段名称，右侧字段值。
4. 固定展示：邮箱、昵称、账号创建时间。
5. 手机号只有在服务端返回非空值时展示，不对空值显示占位行。
6. 页面不展示密码、微信 OpenID、用户状态等敏感或内部字段。

## 数据与接口

个人页首先使用本地会话中已有的用户 ID、邮箱和昵称渲染基础信息，随后请求服务端获取完整且最新的资料。

在完成前端页面、路由与交互后，最后增加认证接口：

```http
GET /api/users/me
Authorization: Bearer <用户 JWT>
```

接口只读取 JWT 对应的当前用户，返回：

```json
{
  "id": 1,
  "email": "user@example.com",
  "nickname": "用户昵称",
  "phone": "13800000000",
  "created_at": "2026-08-08T00:00:00Z"
}
```

其中 `phone` 可为 `null`。服务端不得信任客户端提供的用户 ID，也不得返回密码、OpenID 或状态字段。

## 状态处理

- 未登录访问 `/profile`：重定向首页，并触发现有登录弹窗。
- 初次请求未完成：保留基础资料，同时显示简短加载状态。
- 接口失败：显示“资料加载失败”和返回首页链接；不清除当前登录会话。
- 已登录用户点击账户区域：跳转过程不影响主题状态和其他侧栏功能。

## 验证范围

- 账户区域可点击并跳转到 `/profile`。
- 未登录访问受保护路由时会回到首页并打开登录弹窗。
- 有手机号和无手机号时，资料列表的展示均正确。
- 接口只返回当前认证用户允许暴露的字段。
- 前端生产构建与后端测试、构建通过。

## 范围边界

- 不做资料编辑、邮箱验证、手机号绑定或密码修改。
- 不修改现有移动端和管理后台页面。
- 不复用或改造微信小程序登录链路。
