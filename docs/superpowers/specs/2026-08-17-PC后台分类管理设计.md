# PC 后台分类管理设计

## 目标

在 PC 后台提供完整的分类管理能力：按名称搜索、展示分类全部字段、拖拽排序、新增、改名，以及带文章迁移保护的删除流程。

## 页面与数据

- 新增管理端路由 `/admin/categories` 和分类管理页面。
- 左侧导航在“文章管理”之后新增“分类管理”。
- 列表展示分类表字段 `id`、`name`、`description`、`sort`、`created_at`、`updated_at`，并额外展示后端已提供的 `article_count`。
- 顶部搜索框按分类名称请求 `GET /api/admin/categories?keyword=`。
- 搜索结果只读，拖拽入口禁用；清空关键词后恢复完整可排序列表。

## 排序规则

1. 完整列表使用拖拽调整顺序。
2. 每次拖拽结束后，前端按当前从上到下的 ID 顺序调用现有批量排序接口。
3. 后端在同一事务内将首项写为总数、末项写为 1，因此 `sort` 值越大，分类越靠前。
4. 公共分类接口和管理端分类接口均按 `sort DESC` 查询，保证前台分类页、文章编辑分类选项和后台列表顺序一致。

## 新增与改名

- 新增按钮打开表单弹窗，填写分类名称和描述；排序值由后端自动分配为当前最大值加 1。
- 改名按钮打开表单弹窗，允许修改名称和描述；名称不能为空且最大长度遵循数据库字段限制。
- 后端校验分类名称不重复，防止并发或绕过前端造成同名分类。

## 删除流程

1. 点击删除先调用文章数量接口。
2. 无文章：显示普通确认弹窗，确认后删除。
3. 有文章：显示删除方式选择。
   - 强制删除：要求输入精确文本 `确认删除` 才启用删除按钮；服务端收到强制删除标识后删除分类及其文章。
   - 迁移删除：选择其他分类，服务端在同一事务中迁移该分类全部文章，再删除原分类。
4. 后端删除接口重复校验文章数量、强制确认标识和迁移目标，拒绝将文章迁移到自身或不存在的分类，保证前端流程不能被绕过。

## 接口调整

- 复用既有分类列表、创建、更新、批量排序、文章数量和迁移接口。
- 扩展删除接口以接受 `force` 与 `confirm_text`，并支持迁移参数；删除和迁移在一次服务端事务内完成。
- 保持现有公开分类接口路径不变，仅统一排序方向。

## 验证

- 搜索、清空搜索、拖拽重排后重新进入前台分类页，确认顺序一致。
- 新增和改名成功后列表即时刷新。
- 分别验证无文章删除、有文章强制删除、迁移后删除、错误确认文本和迁移到自身的失败路径。
- 执行前端 `npm run build` 与后端 `go test ./...`。
