# PC 后台分类管理 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 在 PC 后台实现可搜索、可拖拽排序、可安全新增修改删除的分类管理页面，并使前台按相同顺序展示分类。

**Architecture:** 后端复用既有分类管理路由，在服务层统一分类名称校验、排序值分配和删除事务；前端新增独立分类管理页，用浏览器原生拖拽事件在完整列表状态下调整顺序。搜索状态不允许排序，删除流程根据文章数量在前端选择强制删除或迁移删除，后端再次校验所有安全条件。

**Tech Stack:** Go、Gin、GORM、MySQL、Vue 3、Vue Router、原生 HTML Drag and Drop、Vite。

### Task 2: 强化分类创建与删除服务端安全规则

**Files:**
- Modify: `blog/models/dto/request.go`
- Modify: `blog/internal/handler/handler.go`
- Modify: `blog/internal/service/service.go`
- Modify: `blog/internal/repository/repository.go`
- Test: `blog/internal/service/category_management_test.go`

- [ ] **Step 1: 写服务层失败测试**

覆盖以下情况：重复分类名创建失败；创建分类自动取得最大排序值加一；有文章分类缺少 `确认删除` 时删除失败；迁移目标与原分类相同或不存在时失败；迁移成功后原分类删除。

- [ ] **Step 2: 扩展删除请求与仓储事务方法**

为删除分类请求定义 `force`、`confirm_text` 和 `target_category_id`；新增仓储事务方法，在迁移模式下更新文章分类后删除原分类，在强制模式下删除原分类及关联文章。

- [ ] **Step 3: 在服务层执行规则校验**

创建时检查名称非空、长度不超过 50、名称唯一，并在排序值未指定时自动置为当前最大值加一。删除时查询文章数量：无文章直接删除；有文章仅接受精确确认文本的强制删除或有效迁移目标。

- [ ] **Step 4: 在处理器中绑定并传递删除请求**

删除处理器读取 URI 分类 ID 与 JSON 请求体，调用服务层安全删除方法；错误使用现有响应码映射返回。
